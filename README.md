# Purrfect 🐾 — дневник любимца

**Версия v1.0 (Smart Nutrition 2.0 alpha).** Мобильный PWA для ухода за питомцами: профиль, дневник, календарь, вет-помощник и общие семейные записи через Firebase.

## v1.0 — Smart Nutrition 2.0 (экспериментальный разбор)
- Из текста аналитических компонентов извлекаются проценты белка, жира, клетчатки, золы, влажности, омега-3/6, кальция и фосфора (при распознанных названиях с символом %).
- Таблица показывает исходные значения и, если известна влажность менее 100%, расчёт на сухое вещество.
- Неизвестная влажность не оценивается по типу корма; при ней в сухом веществе выводится прочерк.
- Повторные противоречивые показатели скрываются с предупреждением. Данные этикетки проверяются вручную.
- Никаких медицинских оценок качества корма или рекомендаций по лечебным диетам по этим цифрам. Проценты могут быть округлены, иметь границы минимум/максимум.
- Изменения применяются к старым карточкам без миграции данных — заново вносить ранее введённый состав не нужно.

## v0.9 — фильтры истории и переходы
- Фильтры хронологии: все события, питание (включая реакции), наблюдения и вес.
- Кнопка перехода из хронологии в подробности реакции, затем к связанной карточке корма.
- Для старых реакций без ID показывается сохранённое название и объяснение отсутствия карточки.
- Изменение фильтра — локальный интерфейс, не требует записи в семейный документ.

## v0.8.2 — исправление

## v0.8.1 — связанная история ухода
- Наблюдения питания привязываются к конкретной сохранённой карточке корма по ID; старые наблюдения по названию остаются доступными.
- Дневник показывает общую хронологию корма, реакций, симптомов и веса.
- Памятка ветеринару включает свежие реакции на корм, не приписывая им причинность.
- История сортируется по дате; это не доказательство связи между событиями.

## v0.8 Smart Nutrition (первая версия)
- Структурированная карточка корма: тип, вид, жизненный этап, заявленная полнорационность, ингредиенты и аналитические компоненты.
- Прозрачные предупреждения на основе данных с этикетки. Это не лабораторный анализ и не ветеринарное назначение.
- Дневник реакции на питание с историей для каждого питомца.
- Совместимость со старыми записями и семейным документом (новое необязательное поле foodReactions).
- Не используйте выводы для выбора лечебной диеты без ветеринара.

## Возможности v0.6, сохранены
- Список участников семьи с обозначением владельца и текущего пользователя.
- Владелец может отозвать доступ к семье у другого участника.

## Обязательно перед тестом новых ролей
**Замените правила Firestore** в Firebase Console → Firestore Database → Rules точным содержимым файла [firestore.rules](./firestore.rules) и нажмите Publish. Коммит кода на GitHub сам по себе НЕ обновляет опубликованные правила Firestore. Без этого новые кнопки управления семьёй могут отвечать ошибкой permission-denied.

Сначала протестируйте функции на тестовой семье, не на настоящих данных.

## Ограничения
- Почтовая ссылка-приглашение только заполняет ID семьи; владелец должен отдельно добавить UID нового участника.
- Синхронизация пока перезаписывает один общий документ целиком; параллельные правки могут конфликтовать. Не используйте как готовое коммерческое решение.
- В интерфейсе пока показаны ID участников, а не их адреса и имена — данные чужих Firebase Auth-аккаунтов не раскрываются.
- Отзыв доступа запрещает дальнейшие облачные операции, но не стирает ранее загруженные локальные данные с чужого устройства.
- Сначала скачивайте резервную копию через «Ещё → Скачать резервную копию».
- Firebase Admin SDK, приватные ключи, пароли и личные резервные копии не добавлять в публичный репозиторий.
